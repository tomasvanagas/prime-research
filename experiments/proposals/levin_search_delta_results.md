# Levin Universal Search on delta(n) — Results

**Script:** `levin_search_delta.py`
**Run date:** 2026-04-26

## What was tested
Bounded enumeration of all RPN programs of length ≤ L over a tiny DSL,
checking whether any reproduces `delta(n) = p(n) - round(R^{-1}(n))` for
n = 1..N consecutively.

DSL alphabet: `{n, 0, 1, 2, 3, +, -, *, //, %, L (bit-length), S (isqrt)}`
(11 tokens). Programs that violate stack typing are skipped during
enumeration.

## Results

### Search summary
| max_len | Programs enumerated | Best consecutive match | Best program | Time |
|---|---|---|---|---|
| 3 | 108 | 3/30 | `n n -` (always 0) | 0.0s |
| 4 | 620 | 4/30 | `1 n S -` (1 − isqrt(n)) | 0.0s |
| 5 | 5,804 | 4/30 | `1 n S -` | 0.1s |
| 6 | 44,332 | 4/30 | `n n // n S -` | 0.2s |
| 7 | 415,788 | 5/50 | `n 1 - S n L -` | 1.8s |
| 8 | 3,606,060 | 9/50 | `n 1 - S n 2 // -` (isqrt(n-1) − n//2) | 18.6s |

### Baselines (constant programs, total matches not consecutive)
- Constant 0 matches 8/30 of delta values.
- Constant -1 matches 6/30 of delta values.

### What the best program does
`isqrt(n-1) - n//2` happens to coincide with delta(1..9), but breaks at
n = 10:
```
n=1..9   delta = [0, 0, 0, -1, 0, -1, -1, -2, -2]   prog = same
n=10    delta = 0     prog = isqrt(9) - 5 = -2     ✗
```
This is a small-input coincidence, not a genuine compression of delta.

## Verdict
**CLOSED.** Failure mode: **Information loss (I)** — no RPN program of
length ≤ 8 in our 11-token DSL fits delta(n) for n = 1..50 (or even
n = 1..10).

This is a concrete *Kolmogorov-style lower bound*: delta(1..50) is not
generated by any program with a description length ≤ 8 RPN tokens (≈ 28
bits of program code) in this primitive-recursive DSL. To significantly
extend the search:
- Length 9 enumeration: ≈ 35M programs (~3 minutes).
- Length 10: ≈ 350M (~30 minutes).
- Length 12: ≈ 35B (intractable).

By Levin's theorem, if delta were computable by a length-c program in
this DSL, search of depth c would find it. Our search of depth 8 closes
the bottom of the K-complexity ladder.

## Caveats / paths to extend
1. **Different DSL.** A DSL with `gcd`, `mod 6`, `prime indicator` builtin
   would be more expressive. But these are non-elementary and inflate
   "program length" in an awkward way.
2. **Floating-point DSL.** Allow operations like `log`, `sin`, `sqrt` over
   reals, then `round`. This adds expressivity but many small programs
   match by coincidence, lowering the discriminative power.
3. **Levin time-bound search**: instead of fixed length, search programs
   of (length + log runtime) ≤ B. Marginal impact at this scale.

## Connection to existing results
The result complements the project's pseudorandomness findings: delta(n)
is uncompressible in *another* sense — small program search. Informally
this is consistent with delta(n) being incompressible in a Kolmogorov
sense, giving a quantitative lower bound on the description length.
